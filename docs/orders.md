# 订单与库存事务

Step11 已接通创建、读取、确认、取消 API 和页面。token 的 sub 是唯一所有者来源，SQL 查找/锁定同时限制订单 ID 和 owner_sub；不存在和非本人（含管理员）统一404。请求中的价格、总额、owner 等未知字段拒绝。

创建先将 UUID 小写、按商品 ID 排序，并拒绝重复商品。对 owner/key 取得 PostgreSQL 事务级 advisory lock，再按唯一键查看已存订单。相同规范化输入返回200同一订单，不同输入409；比较先重新规范化 JSONB，避免键顺序造成错误冲突。新单201，保存代码/名称/单价快照及服务器计算的 bigint 总额；商品缺失整个创建回滚。创建只短暂读锁商品取得一致快照，不扣减库存。

确认/取消先锁本人的订单行，再读取最新状态。需要改库存时按 UUID 升序锁所有商品。确认先检查所有明细库存，再扣减全部库存和更新 confirmed 状态；不足409，库存和状态整体回滚。取消 draft 不返还库存，取消 confirmed 全量返还一次；重复确认/取消返回既有状态，不重复扣减/返还。确认 cancelled 返回409。订单更新与库存处于同一个 ReadCommitted Prisma 事务， DTO 在事务成功后发送。

每次事务 lock_timeout=2秒、事务上限10秒。仅明确回滚的 SQLSTATE 40001/40P01/55P03 或 Prisma P2034 重试整个事务，最多2次（共3次），短暂随机退避；耗尽503。未知连接/提交结果不自动重试。浏览器请求失败后复用创建 UUID；确认/取消依靠状态幂等。死锁、超时耗尽及复杂竞争的重点验证在Step12。

前端创建/确认/取消在执行时阻止二次提交，数量修改后才重建创建key。创建成功显示服务器快照与总额；状态改变用 Query Client 更新缓存，并失效商品查询；返回商品页取得最新库存。登录状态改变清除私有缓存。订单编号显示在详情中，可通过链接再次查看自己的订单。

只新增2组数据库/API测试：状态/幂等/权限/价格快照/多商品回滚，以及两套API Client的独立PostgreSQL连接竞争。并发测试先由第三连接锁库存，通过 pg_stat_activity 确认两个事务同时等待锁后释放，断言成功1、不足1、库存0；同时检查同key并发创建只保留一单。

只新增1组浏览器场景，承接 E2E-ORDER-CREATE/OWNER/STOCK：真实登录、首次创建成功但响应被测试中断后同key重试、确认→取消库存5→3→5、重复点击防护、多商品不足与draft取消不返库存、另一身份的404。完整 E2E-FLOW 及更全面实际并发/故障回滚仍在Step12验证。浏览器测试生成少量 ORD-* 夹具，均为本地/CI测试商品。
